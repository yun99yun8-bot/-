# TRON 1分钟期数统计监控 v4

## 本版本重点修正

- 每天固定 **1440期**。
- 当天期数显示为 **0001～1440**。
- 到 `1440期` 后，第二天重新从 `0001期` 开始。
- 每天 `1440 ÷ 20 = 72` 个20组周期。
- 第17期到达后生成并锁定第20期的统计预判；第18、19期不会改变预判。
- 第20期到达后记录实际单双，并保存命中/未命中。
- 周期数据库改为“日期 + 第几组”，所以每天的第1组不会覆盖前一天第1组。
- 历史数据继续累计保存，最近60期统计跨天连续统计。
- 平台期号仍保留完整 `YYMMDD + 当天分钟序号`，页面顶部同时显示当天 `0001～1440期`。

## Render

Build Command:
`pip install -r requirements.txt`

Start Command:
`python app.py`

环境变量：

- `TRON_PRO_API_KEY`：你的 TronGrid API Key
- `APP_TIMEZONE`：默认 `Asia/Shanghai`
- `POLL_SECONDS`：默认 `1`
- `DB_PATH`：默认 `tron_history.db`
- `BLOCK_ANCHOR`：2026-09-24 当天00:00对应的基准区块，默认 `86502288`

## 注意

- 不要把 TronGrid API Key 写进代码或发到聊天里。
- Render 如果没有 Persistent Disk，服务重启/重新部署后 SQLite 历史可能丢失；需要长期保存时配置持久磁盘或外部数据库。
- 每天新的基准区块如果没有人工设置，程序会根据当前链高度估算并标记为非确认锚点；如平台实际区块对应关系有变化，需要校正 `BLOCK_ANCHOR`/anchors。
- 统计预判只是根据已经产生的历史数据做统计，不代表下一期一定出现。
