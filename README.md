# v8god 0.0.5

基于 v8god 0.0.3 的安全升级版。部署前仍建议让 V10.6.3 完成 20 万原始区块与 10000 期本地回填。

## 四个板块
1. 首页：最新开奖、当前遗漏、最近20期、单0–单7历史最长遗漏、数据完整性状态。
2. AI练习实验室：固定10000期、24种独立方法、两套综合方案、遗漏条件概率、赔率分组与有限跟单模拟。
3. 推荐方案：点击开始后实时观察；可输出 WAIT/观察候选，不强迫每期下注。
4. 策略中心：两个小板块：A 智能推荐模式；B 自由策略模式（自由选单0–7、遗漏阈值、固定金额、止盈止损，并先用10000期回测）。

## 数据保护 / 修复
- 不清库；沿用现有 PostgreSQL 数据。
- `period_key + group_no` 冲突时更新而非重复插入。
- Worker 每5分钟执行校准记录修复、最近期自修复并重建遗漏。
- Web 显示完整期/异常单值检查。
- 追赶最新开奖仍须等历史回填状态 `complete` 后才启动。

## 重要
历史回测、条件概率、赔率模拟均不保证未来盈利。推荐模式在历史证据不足时应显示 WAIT。


## 0.0.5 稳定性补强
- 固定10000期练习集一旦锁定，实时新数据不会把训练窗口向前滑动。
- 遗漏推荐读取完整阈值表，避免低遗漏阶段因只保留末20个阈值而错误显示样本不足。
- 完整性检查新增重复区块和每期20组集合检查。
- 重型10000期全回放改为每5分钟一轮，避免10秒重复全量计算拖垮Worker；实时页面仍持续刷新。

## 0.0.6 AI 对接结果表
本桥接版不改变0.0.5采集/回填/练习逻辑，只新增只读接口 `/api/ai-handoff`。固定10000期完成后，该接口输出数据集起止期、训练轮次、A/B综合方案训练与样本外命中率、Top方法、最近验证记录以及是否真实达到80%门槛。0.0.6直接读取同一PostgreSQL中的 `shen_practice_runtime` / `shen_practice_rounds`，因此无需把服务器训练数据下载到本地再上传。`qualified80=true` 只有在固定10000期已锁定且最佳方案样本外命中率>=80%时出现。

## AI训练完整版增量
- AI实验页：`/ai-lab`
- API：`/api/ai-lab`、`/api/ai-training/control`
- 达到80%后自动成为可用候选，但训练**不会**因为80%而停止；继续研究95%+。
- “采用当前AI”只锁定当前采用版本，后台训练继续；以后出现更好的>=80%冠军可记录并供0.0.6读取。
- “停止训练”只暂停AI训练线程，不停止TRON采集、开奖写库、遗漏和网站。
- 哈希分析只允许使用预测时已经存在的哈希数据，禁止目标第20组哈希泄漏。

## 三服务版（0.0.5）
本包将运行职责拆为三个 Render 服务，并继续共享同一个 PostgreSQL：
- `tron-monitor`：Web/API 与 `/ai-lab`，不执行重训练。
- `tron-monitor-worker`：TRON 最新数据追赶、开奖记录和数据修复；不执行 AI 训练。
- `tron-monitor-ai-worker`：只负责固定 10000 期 AI/哈希特征研究与冠军模型保存。

AI 达到 80% 后可被采用，但 AI Worker 默认继续研究 95%+；“采用当前AI”和“停止训练”是两个独立操作。停止训练不会停止采集服务或网站。

部署时三个服务的 `DATABASE_URL` 必须指向同一个现有 PostgreSQL。不要新建第二个数据库，不要清库。AI 实验页仍为 `/ai-lab`。

## 360复原审计加强（部署前必读）
- 新增只读接口 `/api/audit360`：对固定10000期、共20万“期内组记录”逐组从原始 hash 独立复算号码和单几，并核对360映射、group block、raw hash。
- AI Worker 启动前强制运行同一审计；任何不一致直接退出，禁止用错误数据训练。
- 重要修正：10000期并不必然对应200000个“唯一”原始区块。360切换时目标区块累计校正-2，相邻期会复用2个区块，所以当前窗口出现199944个唯一原始区块可能正是公式导致，并非自动等同于缺56块。接口会按实际训练窗口计算 expectedUnique 后再判断。
- 审计是只读的，不删除、不改写开奖记录。
